\chapter{Introduction}

Text-to-image (T2I) models can produce detailed images from very short
natural-language prompts. Their outputs may be visually coherent and
aesthetically convincing, but visual plausibility does not imply factual
knowledge. A model may generate a plausible castle, animal, or portrait without
showing which properties distinguish the requested entity from related entities.
It may also add contextual details that are not supported by the entity's
real-world description.

This distinction matters when generated images are used for educational
material, search interfaces, knowledge bases, or other multimodal applications.
In these settings, an image may be interpreted as an assertion about the entity.
An incorrect tower shape, an invented historical attribute, or an unrelated
object can therefore turn a visually attractive image into misleading
information.

\section{Motivation}
\label{sec:motivation}

The problem becomes pressing when images are generated automatically for many
entities at once. \citet{brinster2025} built such a pipeline: it
illustrates the entities of a large knowledge base with images from generative
vision models. A pipeline of this kind is only useful if the image generator
knows the entities it is asked to draw. This thesis therefore examines this
precondition and measures what image-generation models know about individual
entities.

Measuring this is harder for an image generator than for a large language
model (LLM). An LLM can be asked questions about an entity, and when it does
not know the answer, it can say so. A text-to-image model has no such option:
it always returns an image, and a model that does not know an entity still
produces a polished picture of something, without signalling that it has
guessed. What such a model knows can therefore only be read off the images it
produces.

For the images to reflect the model's own knowledge, the prompt must not
supply the facts that are being measured. All models in this thesis receive
the same minimal prompt, ``An image of [entity].'', which contains only the
entity name. Such a prompt is called \emph{zero-context} here: it
contains no Wikipedia text, no hints about the entity's appearance, and no
other description. Every correct detail in the image must come from what the
model learned during training.


\section{Problem Statement}

The central question of this thesis is thus not whether a model can
produce a convincing image, but whether the image is correct for the specific
entity it was asked to show. The thesis examines this question for three
current models: GPT Image 2 by OpenAI and two models of the FLUX.2 family by
Black Forest Labs, the large FLUX.2-dev and the much smaller FLUX.2-klein-4B.
The following example shows how far a convincing image and a correct one can
diverge.

Figure~\ref{fig:problem-example} shows the three images generated for the
entity \emph{Dennis Dart}. Readers outside the United Kingdom will rarely know
this name, which is what makes it a useful example. The Dennis Dart is a
single-decker midibus chassis built by the British manufacturer Dennis from
1989 onwards; more than 12,600 were produced, most of them for British bus
operators~\citep{wikidennisdart}. A correct image therefore shows a short
single-deck bus, typically in the colours of a British operator. The name itself
gives no hint of this: ``Dennis'' is a common first name and a ``dart'' is a
small throwing object. A model that does not know the entity has to guess from
these two words.

The three models guess differently. GPT Image 2 draws a single-deck bus with
``DENNIS Dart'' written on the front and the logo of the British operator First.
FLUX.2-dev draws a red and grey hand-held device on a wooden floor, with
``Dennis Dart'' as a heading above a line of unreadable pseudo-text.
FLUX.2-klein-4B draws a portrait of a smiling grey-haired man, reading
``Dennis'' as a person's name. Both FLUX images are sharp and photorealistic; a
reader who does not know what a Dennis Dart is cannot tell that they are wrong.

The example shows that an image can go wrong at different levels. It can show
the wrong kind of object, as the device and the portrait do. It can show the
right kind of object without the details that make it this particular entity,
such as a generic city bus instead of a small single-deck bus. And it can
contain details that are simply false. Because a convincing appearance hides
all three kinds of error, the images have to be checked systematically. This
thesis does so along the following research questions.

\section{Research Questions}
\label{sec:rqs}

The thesis addresses three research questions:

\begin{description}[leftmargin=2.8cm,style=nextline]
\item[RQ1:] For how many real-world entities can T2I models correctly predict
their type?
\item[RQ2:] For how many real-world entities do T2I models know descriptive
features that distinguish them from related entities?
\item[RQ3:] Of the facts expressed in generated images for a given entity, how
many are true?
\end{description}

All three questions are answered with the same procedure, which
Chapter~\ref{chap:methodology} describes in detail. Each model generates one
image per entity from the zero-context prompt. A vision-language model (VLM),
called the \emph{judge} in this thesis, then describes each image without
being told which entity it is supposed to show. Besides a short description and
a guess of the object type, the judge writes down short, self-contained
statements about what is visible, such as ``The vehicle is a bus'' or ``The
sky is clear and blue''. These statements are called \emph{propositions}; they
make the content of an image countable. In a second step, the judge compares
its output with the introduction of the entity's English Wikipedia article,
called the \emph{lead summary}. For RQ1 and RQ2, the comparison uses a type and
a distinctive feature that were annotated in advance for a curated set of
entities; for RQ3, the judge counts how many propositions the lead summary
shows to be false.

\section{Contributions}

The thesis makes four contributions.
\begin{enumerate}
\item A benchmark of 298 real-world entities: 100 curated entities from four
domains, each annotated with an expected type and a distinctive visual feature,
and 198 randomly sampled Wikipedia entities in three popularity tiers defined
by article size.
\item A public corpus of 885 images generated by GPT Image 2, FLUX.2-dev, and
FLUX.2-klein-4B from the same zero-context prompt, together with a record of
the nine prompts that OpenAI's safety system refused.
\item A two-step evaluation in which a vision-language judge first describes
each image without knowing the entity and then checks the resulting
propositions against the Wikipedia lead summary, yielding type match (RQ1),
feature presence (RQ2), and the share of false propositions (RQ3).
\item An analysis of the results by domain and popularity, a catalogue of
typical failure patterns, and a comparison with published estimates of the
factual knowledge of language models.
\end{enumerate}
Code, images, evaluation results, and all derived tables and figures are
available at \url{https://github.com/mrEkso/t2i-factuality-benchmark}.

\section{Text-to-Image Models}
\label{sec:t2i-models}

Most current text-to-image models build an image step by step from random
noise. Diffusion models learn to remove the noise gradually, guided by an
encoding of the text prompt~\citep{rombach2022,podell2024}. Rectified-flow
models, a more recent variant, learn a straight path between noise and
image~\citep{esser2024}. How closely the result follows the prompt depends on
the text encoder and on the quality of the image captions used in
training~\citep{betker2023}. The training objective rewards images that match
their captions and look realistic; it does not reward factual correctness for
a named entity. Whatever a model knows about an entity is therefore a
by-product of its training data.

The three models studied in this thesis differ in how openly they are
available. FLUX.2-dev and FLUX.2-klein-4B by Black Forest Labs are
\emph{open-weight} models: their trained parameters are public, so they can be
run on one's own hardware. Both combine a language model, which encodes the
prompt, with a rectified-flow transformer, which generates the
image~\citep{flux2,flux2klein}. GPT Image 2 by OpenAI is a proprietary model.
It runs only on OpenAI's servers and can be used only through OpenAI's
programming interface (API); its architecture and size are not
disclosed~\citep{gptimage2}.


\section{Knowledge Bases and Visual Representations}
\label{sec:kb-illustration}

A knowledge base stores facts about entities, usually as
subject--relation--object \emph{triples} such as (Dennis Dart, manufacturer,
Dennis). Many entities in public knowledge bases such as Wikidata have no
image, and earlier work has used generative models to fill this gap:
\citet{abuahmad2023} generated images for Wikidata entities from their triples,
and \citet{brinster2025} illustrated a knowledge base that had itself been
extracted from a language model. In both cases, the generated image serves as
the illustration of the entity. This thesis asks the preceding question,
namely whether such images can be trusted. It uses Wikipedia only as a source
of entity names and reference descriptions and does not build or complete a
knowledge base.


\section{Evaluating Visual Factuality}
\label{sec:eval-factuality}

Deciding whether a generated image can be trusted requires an evaluation of
its content, not only of its quality. Image-quality metrics assess realism,
and similarity scores based on CLIP, a model that maps images and texts into a
shared representation, measure how
well an image matches a caption~\citep{radford2021,hessel2021}. Neither checks
whether the image shows the correct entity or contains false attributes;
surveys treat image quality, prompt alignment, aesthetics, and factual
correctness as separate objectives~\citep{hartwig2024}. Broad benchmarks cover
many such aspects at once: HEIM evaluates, among others, alignment, quality,
and bias, and T2I-CompBench++ tests whether several objects and attributes
named in one prompt are combined correctly~\citep{heim2024,t2icompbenchpp2024}.


For prompt alignment, the field has moved from single similarity scores to
question answering over atomic claims: TIFA and VQ$^2$ derive questions from the
prompt and answer them with a visual question-answering (VQA) model, that is,
a model that answers questions about an image~\citep{tifa2023,vq2}. The same idea has been applied to factuality.
I-HallA measures factual errors in generated images with curated
questions~\citep{ihalla2024}, T2I-FactualBench evaluates knowledge-intensive
concepts with multi-round question answering~\citep{t2ifactualbench2025},
KITTEN evaluates how faithfully generated images depict real-world
entities~\citep{kitten2024}, and FAGER builds a factual rubric from language-model
knowledge and reference images~\citep{fager2026}. Large proprietary
vision-language models such as GPT-4V have also been used directly as
evaluators~\citep{gpt4v2024}. This thesis follows the claim-based approach with
two differences. First, the claims are extracted from the image by a judge that
does not know which entity the image should show. Second, they are checked
against an external text reference, the Wikipedia lead summary. Instead of a
proprietary model, the judge is Gemma~4~31B, an open-weight VLM by Google
(Section~\ref{sec:model-selection}), so that the evaluation can be re-run
without a commercial API; Section~\ref{sec:limitations} discusses the cost of
this choice.


\section{Hallucinations and Long-Tail Entities}
\label{sec:hallucinations}

When a generated image shows something false about the entity, this is called
a \emph{hallucination}, a term taken from text generation. Surveys of
hallucination in text generation distinguish \emph{intrinsic} hallucinations,
which contradict the source, from \emph{extrinsic} ones, which the source can
neither confirm nor refute~\citep{hallucinationNLG2023,hallucinationSurvey}.
This thesis counts only the intrinsic kind: a proposition is a hallucination if
the Wikipedia lead summary shows it to be false. A background that the summary
does not mention, for example, is extrinsic and is not counted
(Section~\ref{sec:visual-facts}).

Earlier work has also studied what makes such errors more likely and how to
reduce them. Retrieving real reference images during generation has been
proposed as a remedy~\citep{preventimagehallucination2024}, and DoFaiR shows
that instructions to increase demographic diversity can make images of
historical subjects factually inaccurate~\citep{dofair2024}. A further factor,
and the one studied here, is how well known an entity is. For language models,
this factor is well documented: their factual accuracy drops sharply for
entities that are rarely mentioned on the web~\citep{mallen2023,kandpal2023}.
Image generators may behave in the same way, since they have seen few or no
pictures of rare entities during training. To test this, the benchmark
includes a \emph{Long-tail} tier of entities with very short Wikipedia
articles, which serve as a proxy for low popularity
(Section~\ref{sec:benchmark-design}).


\section{Factual Knowledge in Language Models and Image Generators}
\label{sec:llm-vs-t2i}

For language models, the amount of factual knowledge has been estimated
directly.
GPTKB materializes the knowledge of GPT-4o-mini by recursively prompting the
model for facts about entities; the resulting knowledge base contains
101~million triples about 2.9~million entities~\citep{gptkb2025}. The authors
relate this number to model size: at an estimated 8~billion parameters,
GPT-4o-mini uses about 79 parameters per retrieved triple. A later version built
from GPT-4.1 contains 100~million triples about 6.1~million
entities~\citep{gptkb15}. Controlled experiments on synthetic data give an upper
bound: a language model can store about two bits of knowledge per
parameter~\citep{allenzhu2025}.

No comparable estimate appears to exist for image generators, and their
knowledge differs
from that of LLMs in three ways. First, the unit is different. An LLM states a
fact as a sentence that can be mapped to a subject--relation--object triple. An
image states facts implicitly, and only facts that are visible: a platypus's
bill or a bus livery can be drawn, a birth date or an election result cannot,
except as written text. The facts counted in this thesis are therefore visual
propositions (Section~\ref{sec:visual-facts}), not triples. Second, the
elicitation is different. GPTKB asks many questions per entity and follows links
to further entities; a zero-context image prompt gives the model one attempt per
entity, and the model cannot abstain. Third, the knowledge is stored in
different components. As described in Section~\ref{sec:t2i-models}, the FLUX
models contain a language model:
FLUX.2-dev couples a 24-billion-parameter Mistral vision-language model, which
Black Forest Labs describe as the source of ``real world knowledge'', with a
32-billion-parameter rectified-flow transformer that produces the
image~\citep{flux2}. FLUX.2-klein-4B pairs a 4-billion-parameter transformer
with the Qwen3-4B language model~\citep{flux2klein}. OpenAI does not disclose
the size or architecture of GPT Image 2~\citep{gptimage2}; its predecessor was
introduced as image generation built into GPT-4o, which lets the model ``link
its knowledge between text and images''~\citep{openai4oimage}. An image
generator can therefore fail in two places: its language component may not know
the entity, or it may know the entity while the image component cannot draw
what it knows.

\section{Benchmark Design}
\label{sec:benchmark-design}

The benchmark consists of 298 entities in two subsets that serve different
purposes (Table~\ref{tab:benchmark-composition}). The \emph{curated} subset
contains 100 entities selected by hand, for which the expected appearance is
annotated; it is used for all three research questions. The \emph{Random}
subset contains 198 entities sampled from Wikipedia; it has no annotations and
is used for RQ3 and for the analysis by popularity.

The curated entities come from four domains with 25 entities each: famous
landmarks and architecture, historical figures, rare flora and fauna, and
specific cultural artifacts and foods. The domains cover buildings, people,
living beings, and objects, so that knowledge concentrated in one domain can be
separated from general visual competence. Within each domain, the author chose
entities that are recognizable but differ in how familiar they are. Each
curated entity is annotated with an expected type and a distinctive feature.
The expected type names the class of the entity (for example, ``Castle'' for
Neuschwanstein or ``Mammal'' for Platypus). The distinctive feature is a
visible property that separates the entity from similar ones (for example,
``duck-like bill and beaver-like tail'' for Platypus).

The Random subset tests entities that were not chosen by hand. Its entities
were drawn with the MediaWiki \texttt{list=random} API from the article
namespace of the English Wikipedia; titles containing ``List of'' or
``disambiguation'' were skipped. Each drawn article was assigned to a
popularity tier by its size, measured in bytes of wikitext (the article's
source text) as returned by the MediaWiki API and released as the
\texttt{Wiki\_Length} field: Famous for at least 100{,}000 bytes, Medium for
20{,}000 to less than 100{,}000 bytes, and Long-tail for 500 to less than
20{,}000 bytes. Sampling continued until each tier held 66 entities, so that no
tier dominates the sample.

Article size serves as a proxy for popularity: widely known topics attract more
editors and references, and their articles grow accordingly. The proxy is
imperfect, since a short article can also describe an important but
little-documented topic. The tiers are therefore strata of the sample, not a
claim about how often an entity occurs on the web.


\section{Models and Image Generation}
\label{sec:models-and-image-generation}
\label{sec:model-selection}

The three image generators cover the two settings in which such models are used
in practice: a proprietary service and openly available models. GPT Image 2 is
the image model that OpenAI released in April 2026; it runs only on OpenAI's

model size within one family, and comparing them with GPT Image 2 shows how
open models relate to a commercial one. The selection is not meant as a

Each image is evaluated in two calls to the judge
(Figure~\ref{fig:benchmark-pipeline}). Both calls use temperature~0, which
makes the output as deterministic as possible, and return machine-readable
JSON; Appendix~\ref{sec:judge-prompts} gives the exact prompts. In the first,
\emph{blind} call, the judge sees only the image, not the entity name, and
returns a predicted type, a short description, and a list of propositions about
what is visible. Keeping this call blind prevents the entity name from
suggesting what the judge should see. The second, \emph{grounded} call does not
see the image. It receives the entity name, the Wikipedia lead summary, the
curated type and feature (for curated entities), and the output of the blind
call. It returns the decisions for RQ1 and RQ2 and the number of propositions
that the lead summary shows to be false. Wikipedia titles are resolved through
the MediaWiki search API, and the retrieved lead summaries are cached in the
released evaluation directory. All 885 successful evaluations use a Wikipedia
lead summary as reference; for two curated entities the search returned the
wrong article (Section~\ref{sec:limitations}).




For RQ1, a result is correct if the grounded call accepts the type predicted in
the blind call as compatible with the curated expected type. The blind prompt offers
broad example labels (Building, Person, Animal, Landscape, Object, None) but
does not restrict the answer to them, while the curated types are more
specific. A broad label therefore counts as a match when it covers the expected
type: ``Building'' matches ``Castle'' for Neuschwanstein, and ``Animal''
matches ``Mammal'' for Platypus. A label from a different class, such as
``Person'' for a pastry, is a mismatch. RQ2 is decided separately: it is
correct only if the blind description or propositions clearly indicate the
annotated distinctive feature. Since the grounded call sees only this text, a
feature that is drawn but not mentioned in the blind call counts as absent. Keeping RQ1 and RQ2 apart prevents a broad type match from being taken
as recognition of the entity.

For RQ3, the decision is made per proposition. A proposition that the lead
summary shows to be false, or that contradicts it, is counted as a
hallucination (Section~\ref{sec:hallucinations}); a proposition that the
summary does not mention is not counted. Counting per proposition avoids
treating an image with ten correct claims and one false claim like an image
with a single false claim.

The counts are aggregated per model into the main metric, the hallucination
rate
\begin{equation}
\mathrm{HallucinationRate}(m) =
\frac{\sum_i H_{i,m}}{\sum_i P_{i,m}},
\end{equation}
where $H_{i,m}$ is the number of hallucinations in image $i$ generated by model
$m$, and $P_{i,m}$ is the number of propositions extracted from that image.
This is a pooled rate: it sums hallucinations and propositions before dividing,
so an image with a very short description does not receive the same weight as
a longer one. The Spearman analysis in Section~\ref{sec:fact-count-results}
uses the per-image rate $H_{i,m}/P_{i,m}$ instead.

All rates are reported with 95\% Wilson confidence intervals, a standard
interval for proportions that remains reliable for small samples and for rates
close to 0 or 1. Differences between two models in RQ1 and RQ2 are tested with
two-sided two-proportion $z$-tests.


\section{What Counts as a Visual Fact}
\label{sec:visual-facts}

A language model states a fact in a sentence; an image states facts only
implicitly. The blind call makes them explicit as propositions
(Section~\ref{sec:rqs}), which are the unit counted in RQ3. Not all propositions
carry the same kind of information: those in the corpus are of five kinds.
Table~\ref{tab:fact-types} gives one example of each, taken from the
evaluation file.


\begin{table}[ht]
\centering
\footnotesize
\caption{Kinds of propositions extracted from generated images, with examples
from the evaluation corpus.}
\label{tab:fact-types}
\begin{tabular}{p{2.1cm}p{6.6cm}p{4.3cm}}
\toprule
Kind & Example proposition (entity, model) & Checkable against the lead summary? \\
\midrule
Type & ``The vehicle is a bus'' (Dennis Dart, GPT Image 2) & Yes, almost always \\
Appearance & ``There are multiple vertical fluted columns'' (Parthenon, FLUX.2-dev) & Often, if the summary describes the appearance \\
World knowledge & ``There is a silver fern logo and the text `NEW ZEALAND' on the left side of the chest'' (Heath Streak, GPT Image 2) & Sometimes; here it contradicts ``Zimbabwean cricketer'' \\
Rendered text & ``The text `DENNIS Dart' is written on the front'' (Dennis Dart, GPT Image 2) & Rarely; it mostly repeats the prompt \\
Scene & ``The sky is clear and blue'' (Parthenon, FLUX.2-dev) & Almost never \\
\bottomrule
\end{tabular}
\end{table}

Type and appearance propositions carry most of the entity knowledge.
World-knowledge propositions are the most informative ones: a jersey, a flag,
or a bus livery links the entity to another entity (a country, an operator, a
place), which is the kind of fact a knowledge base stores as a triple. Rendered
text and scene propositions carry little knowledge. A keyword rule applied to
all 6{,}439 propositions of the common set (the 289 entities generated by all
three models; Section~\ref{sec:fair-comparison}) gives a rough picture: 18--24\% of
the propositions describe the background, lighting, or weather, and 9\% (FLUX
models) to 20\% (GPT Image 2) transcribe text written in the image. The
remaining 61--68\% describe the depicted object itself. The rule is simple, so
these shares are approximate.

The distinction matters for RQ3. Since only propositions shown to be false are
counted, scene and text propositions are almost never counted as errors, and an
image that shows only a generic landscape can reach a hallucination rate of
zero (Section~\ref{sec:qualitative-examples}).

\section{Common Set and Missing Evaluations}
\label{sec:fair-comparison}

Not every model produced an image for every entity: GPT Image 2 refused nine of
the 298 prompts through its safety system. Comparing each model on all of its
own images would therefore compare the models on different entities. The main
comparison instead uses the \emph{common set}, the 289 entities for which all
three models produced an image. The nine refusals are recorded separately and
counted neither as correct nor as incorrect, so that a policy decision of the
provider is not mistaken for missing knowledge. Results on all images of each
model, called \emph{available-case} results, are reported only where they show
that the restriction to the common set does not change a conclusion.


\section{Proposition-Count Analysis}
\label{sec:fact-count}

The hallucination rate depends on how many propositions an image yields: a
short description offers fewer chances to be wrong, but also says less about
the entity. The analysis therefore reports the average number of propositions
per image by model and popularity tier alongside the rates. Spearman rank
correlation is used to check whether images with more propositions also have a
larger share of false ones. A coefficient near zero indicates no consistent
monotonic relationship, and values close to $1$ or $-1$ indicate a strong
one.


\section{Weighted Extrapolation to the Full Encyclopedia}
\label{sec:weighted-extrapolation}

The last analysis estimates how many non-contradicted visual propositions a
model would produce if it drew every entity of the English Wikipedia. This puts the results
on the same scale as the estimates of LLM knowledge discussed in
Section~\ref{sec:llm-vs-t2i}. The estimate cannot be obtained by averaging the
three tiers with equal weights, because the benchmark samples the tiers equally
by design, while most Wikipedia articles are short. Such a naive average would
overweight the popular entities.

To correct for this, the population share $w_t$ of each tier was estimated
from Wikipedia's published statistics on article
size~\citep{wikipediaarticlesize2026}. These statistics are expressed in words
rather than bytes of wikitext, so the benchmark thresholds were converted with a
rough factor of 7 bytes per word; the conversion is used only for this
estimate, not for assigning entities to tiers. The resulting shares are about
0.32\% (Famous), 5.3\% (Medium), and 94.3\% (Long-tail). This agrees with the
fact that about 32\% of all English Wikipedia articles are stubs, that is,
articles too short to cover their topic adequately~\citep{wikipediastub2026}.
Because wikitext markup varies across articles, $w_t$ is an order-of-magnitude
estimate rather than an exact population statistic.

The weighted extrapolation for model $m$ is
\begin{equation}
\mathrm{Total}(m) = N_{\text{total}} \times \sum_{t \in \{F,M,L\}}
w_t \cdot \bar{F}_{t,m} \cdot \bigl(1 - \mathrm{HallucinationRate}_{t,m}\bigr),
\label{eq:weighted-extrapolation}
\end{equation}
where $N_{\text{total}} = 7{,}237{,}727$ is the number of English Wikipedia
articles on 18 September 2026~\citep{wikipediasize2026}, $\bar{F}_{t,m}$ is the
average number of propositions per image for tier $t$ and model $m$, and
$\mathrm{HallucinationRate}_{t,m}$ is the pooled hallucination rate for the
same tier and model; both are reported in Chapter~\ref{chap:results}. The
product of the last two factors is the number of propositions per image that
are not shown to be false. It includes scene and
text propositions (Section~\ref{sec:visual-facts}), so $\mathrm{Total}(m)$ is
an upper bound on the number of correct entity facts, not a count of verified
facts.

\section{Type and Feature Recognition}
\label{sec:rq12-results}

RQ1 and RQ2 are measured on the 97 curated entities of the common set, called
the \emph{common curated subset} below. On this subset, the type-match rates
are 77.3\% for GPT Image 2, 79.4\% for FLUX.2-dev, and 73.2\% for
FLUX.2-klein-4B. The available-case rates are almost the same (77.3\%,
80.0\%, and 73.0\%), so the restriction to the common set does not change the
picture.

FLUX.2-dev thus has the highest type-match rate, but the differences are small:
none of the three pairwise tests is significant for RQ1 (GPT Image 2 versus
FLUX.2-dev $p=0.727$, GPT Image 2 versus FLUX.2-klein-4B $p=0.506$, and
FLUX.2-dev versus FLUX.2-klein-4B $p=0.311$). The feature rates differ much
more. GPT Image 2 shows the distinctive feature for 62.9\% of the entities,
FLUX.2-dev for 46.4\%, and FLUX.2-klein-4B for 28.9\%. All three pairwise
differences are significant without a correction for multiple testing (GPT
Image 2 versus FLUX.2-dev $p=0.021$, GPT Image 2 versus FLUX.2-klein-4B
$p<0.001$, and FLUX.2-dev versus FLUX.2-klein-4B $p=0.0118$). With a
Bonferroni correction for three comparisons, which lowers the threshold to
$0.05/3 \approx 0.0167$, the difference between GPT Image 2 and FLUX.2-dev is
no longer significant, while the other two remain so. Recognizing the broad
category is therefore not the same as showing the feature that makes an entity
visually distinctive. Figures~\ref{fig:rq1-category} and~\ref{fig:rq2-category}
break both rates down by curated category.

\chapter{Discussion}

This chapter interprets the results. Section~\ref{sec:answers} answers the
research questions, Section~\ref{sec:discussion-llm} compares the findings with
what is known about factual knowledge in language models, and
Section~\ref{sec:implications} discusses implications and limitations.

\section{Answers to the Research Questions}
\label{sec:answers}

\textbf{RQ1.} The three models draw the correct coarse type for 73--79\% of
the 97 curated entities of the common set, and the differences between them
are not significant. Type recognition is close to perfect for flora and fauna
(92--100\%) and lowest for cultural artifacts and foods (32--40\%); the latter
mainly reflects the generic label ``Object'' assigned in the blind call,
as the much higher feature rates for this category show
(Section~\ref{sec:rq12-results}).

\textbf{RQ2.} The models differ strongly in whether they show what
distinguishes an entity from similar ones: GPT Image 2 does so for 62.9\% of
the curated entities, FLUX.2-dev for 46.4\%, and FLUX.2-klein-4B for 28.9\%.
The gap between RQ1 and RQ2 is largest for the smallest model, which
recognizes the type of 73.2\% of the entities but shows the distinctive
feature for fewer than a third. For these models, knowing the class of an
entity is much easier than knowing how it differs from its neighbours, as the
Platypus example shows (Figure~\ref{fig:platypus}).

\textbf{RQ3.} Of the propositions extracted from the images, 91.0\% (GPT
Image 2), 90.3\% (FLUX.2-dev), and 82.3\% (FLUX.2-klein-4B) are not
contradicted by the lead summary. This share is an upper bound on the share of
true propositions, because the judge cannot confirm what the lead summary does
not mention. For GPT Image 2 the share of false propositions grows from 3.0\%
for Famous to 23.0\% for Long-tail entities, although its Long-tail images
contain fewer propositions; nine of its 13 images in which every proposition is
false are Long-tail entities. Its errors on rare entities thus come from
drawing the wrong thing, not from describing more. The FLUX models show no
consistent popularity effect.

\section{Comparison with Knowledge in Language Models}
\label{sec:discussion-llm}

The population-weighted extrapolation in Table~\ref{tab:extrapolation} puts
the number of non-contradicted visual propositions over all English Wikipedia articles
at about 43~million for each model. This is the same order of magnitude as the
101~million triples that GPTKB extracts from GPT-4o-mini~\citep{gptkb2025}, but
the two numbers measure different things. GPTKB covers 2.9~million entities with
about 35 triples each; the extrapolation assumes one image with about six
non-contradicted propositions for each of 7.2~million articles. About a third of these
propositions describe the scene or transcribe text rather than the entity
(Section~\ref{sec:visual-facts}), so the entity-related part is closer to 25--30
million. Finally, a GPTKB triple is a relational fact elicited by many prompts,
whereas a proposition is only what one image happens to show.

The per-model results nevertheless point in the direction known from language
models. The three generators recognize the coarse type about equally often
(73--79\%, no significant difference), but differ strongly on distinctive
features (63\%, 46\%, and 29\%). The RQ2 ranking follows model size: GPT Image 2, whose size is undisclosed but
whose predecessor was built into GPT-4o, ranks first; FLUX.2-dev, with a 24B
language model and a 32B image transformer, ranks second; FLUX.2-klein-4B, with
4B parameters in each component, ranks last. With three models this is an
observation and not a scaling result, because size, training data, and
architecture change together, and the two FLUX models differ in both
components at once. It is consistent with the view that coarse types are
available even to small models, while entity-specific visual detail requires
more capacity. The popularity effect for GPT Image 2
(Table~\ref{tab:tier-hallucination}) likewise resembles the drop in LLM accuracy
for rare entities~\citep{mallen2023,kandpal2023}.

\section{Implications and Limitations}
\label{sec:implications}

\subsection{Implications}

Visual plausibility is insufficient for using T2I outputs in knowledge-oriented
settings. A generated image may get the entity type right while failing to
include the feature that makes the entity recognizable. Conversely, an image can
look detailed while containing false contextual details. Proposition-level
checking is therefore a useful complement to image-quality metrics.

The examples in Section~\ref{sec:qualitative-examples} also show that the
benchmark score depends on how directly an entity can be drawn. For a concrete
entity such as Dennis Dart, a wrong image produces several explicit
contradictions: a hand-held device or a portrait of a man cannot be a bus
chassis. For an abstract entity such as Freedom of religion in Austria, models
draw landscapes or captioned scenes that contradict nothing in the summary.
The hallucination rate should therefore be read as a measure of false visual
statements, not as a measure of how much the image shows about the entity.

\subsection{Limitations}
\label{sec:limitations}

\paragraph{What RQ3 measures.} The judge counts propositions that the reference
shows to be false. Propositions that the lead summary does not mention are not
counted, so the complement of the hallucination rate is an upper bound on the
share of true propositions. For abstract entities, whose images assert little
that the summary could contradict, a low hallucination count does not show that
the concept was visualized (Section~\ref{sec:qualitative-examples}).

\paragraph{Judge.} All decisions are made by one open-weight model,
\texttt{gemma-4-31B-it}, which is smaller than proprietary evaluators such as
GPT-4V~\citep{gpt4v2024}, and its decisions were not validated against human
judgements. The judge is also not fully consistent: it accepted the label
``Object'' as a type match for artifacts and foods in 27 of 64 cases and
rejected it in the others. Since all three generators were scored by the same
judge, the ranking of the models is expected to be more robust than the
absolute percentages.

\paragraph{Reference.} The Wikipedia lead summary is short, so a visible
detail can be true without being mentioned. Title resolution also picked the
wrong article for two curated entities: ``Montezuma'' resolved to a small
community in New Mexico and ``Ada Lovelace'' to an Nvidia GPU architecture. For
Montezuma, all three models drew an Aztec ruler with a feathered headdress, but
the judge marked the type as wrong and counted 8, 8, and 9 hallucinations.
Correcting this entity would raise each model's RQ1 rate by about one
percentage point and lower each overall hallucination rate by about 0.4 points;
the ranking of the models does not change. The Random entity ``Stardust'' is
probably affected in the same way.

\paragraph{Blind call.} The blind call does not see the prompt, but it does see
any text written inside the image. Models often write the entity name into the picture:
this happens in about 47\% of the GPT Image 2 images, 24\% of the FLUX.2-dev
images, and 14\% of the FLUX.2-klein-4B images (keyword count). In these cases
the judge can read the name, which makes RQ1 easier than intended and
favours GPT Image 2 most.

\paragraph{Sample.} The curated subset is small (97 entities in the common set)
and was annotated by one person. Each entity was generated once per model
without a fixed seed, so the results do not capture the variation between
repeated generations. The Random subset is stratified by design and does not
reproduce the distribution of Wikipedia; Section~\ref{sec:weighted-extrapolation}
corrects for this only in the extrapolation.

\paragraph{Refusals.} GPT Image 2 refused nine prompts, including three
historical figures. The common set keeps these refusals from being scored as
errors, but conclusions about GPT Image 2 apply only to the entities it
generated, and the missing entities are not a random sample.

\paragraph{Proposition count.} The number of propositions is only a proxy for
how much an image shows: a longer description is not necessarily more
informative, and a shorter one is not necessarily more accurate.

\chapter{Conclusion and Future Work}

This thesis introduced a benchmark for the factual knowledge of text-to-image
models and applied it to GPT Image 2, FLUX.2-dev, and FLUX.2-klein-4B. Three
findings stand out. First, recognizing the type of an entity is not the same as
knowing it: the models draw the correct type for 73--79\% of the curated
entities, but the distinctive feature for only 29--63\%. Second, 9--18\% of the
visual propositions contradict the lead summary, and for GPT Image 2 this share
grows from 3\% for popular to 23\% for rare entities. Third, the most severe
errors come from reading the entity name as something else, such as a man
called Dennis instead of a bus model; the image then looks convincing and is
entirely wrong. Compared with language models, whose factual knowledge has been
materialized at the scale of $10^8$ triples, the knowledge of image generators
is harder to elicit and limited to what can be drawn.

Future work should validate the judge against human annotations on a sample of
propositions and use more than one judge. A longer reference than the Wikipedia
lead would separate false propositions from unmentioned ones. Repeated
generations per entity, a closed label set for the blind call, more
models, and a larger, naturally sampled Long-tail set would allow stronger
conclusions.

\section{Reproducibility Files}

The benchmark entities are stored in the entity CSV. Generated images are
organized by model and category. The evaluation results contain one row per
successful entity--model pair, and the full benchmark release includes the
analysis script, the evaluation outputs, and the generated image folders. The
analysis script regenerates coverage tables, common-set comparisons, tier-level
hallucination tables, proposition-count tables, correlations, and figures from
these inputs. This separation between raw rows and derived tables allows the
reported values to be recomputed after changing a metric or adding another model.

The generation script uses ten concurrent workers and skips existing files, but
it does not record per-request durations. The evaluation log records a
wall-clock run from 13 August 2026 23:05:48 to 14 August 2026 03:02:26 for the
766 queued image tasks, approximately 3 hours 57 minutes including Wikipedia
prefetching and retries. This is a reproducibility observation for that run,
not a general speed benchmark; request latency depends on provider load,
concurrency, and retries.

The public code and generated assets are available at
\url{https://github.com/mrEkso/t2i-factuality-benchmark}.

\section{Judge Prompts}
\label{sec:judge-prompts}

Both calls use \texttt{gemma-4-31B-it} with temperature~0, JSON output, and the
system message ``You are a strict JSON-only API. Always return valid JSON
without markdown wrapping.'' Placeholders are shown in angle brackets.

\paragraph{Call 1 (blind).} The image is attached to the message.
{\small
\begin{verbatim}
You are an objective computer-vision classifier. You are NOT told what
this image is supposed to depict - judge only what is visually present.

Output a raw JSON object with exactly these keys:
1. "predicted_type": The primary object type shown (e.g., Building,
   Person, Animal, Landscape, Object, None).
2. "description": A brief text description of the main visual elements.
3. "propositions": A list of short, atomic factual claims about what is
   visually shown (e.g., ["The building has a round tower", "There is a
   river in the foreground"]).
\end{verbatim}
}

\paragraph{Call 2 (grounded, curated entities).} No image is attached. For
Random entities, the expected type and feature and keys 1 and 2 are omitted.
{\small
\begin{verbatim}
You are a strict fact-checking judge. You are given:
- The real-world entity name: "<entity>"
- Reference text about this entity (from its Wikipedia summary):
  """<Wikipedia lead summary>"""
- An expected object type for this entity: "<expected type>"
- An expected unique feature for this entity: "<expected feature>"
- Visual observations made by a separate, blind image classifier (it did
  NOT know the entity name), about a generated image that is supposed to
  depict this entity:
  predicted_type = "<predicted type>"
  description = "<description>"
  propositions = [<propositions>]

Using ONLY the ground truth text above (plus general knowledge only if
the ground truth text is marked unavailable), output a raw JSON object
with exactly these keys:

1. "rq1_type_match": Boolean. Does predicted_type match the expected
   reality of "<entity>"?
2. "rq2_feature_present": Boolean or null. Do the propositions/description
   clearly indicate the feature "<expected feature>"? If expected_feature
   is "N/A", output null.
3. "rq3_hallucinations_count": Integer. How many propositions are FALSE
   or contradicted by the ground truth text?
4. "rq3_hallucinations_details": Short string explaining which
   propositions are wrong, or "None" if all are consistent with the
   ground truth.
\end{verbatim}
}
